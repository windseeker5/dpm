{# Data Table — the shared shape behind the Passports/Sign-ups/Activities list pages, which today each hand-roll their own copy of this table (search box + filter tabs + with d-none/d-md-table-cell columns + Bootstrap .dropdown row actions). Three pieces: - table_toolbar(): filter_tabs() (centered) + a search icon collapsed to the left of them. Same markup at every width — only CSS (mp-components.css, a *container* query on the toolbar's own rendered width, not the page viewport) and JS (mp-table-toolbar.js) change the *behavior*: wide (>=768px): the input is always visible, no click needed. narrow (<768px): collapsed to just the icon; clicking it replaces the tab row entirely with a full-width input; clearing/ closing restores the tabs. A page filtering/searching via real navigation (a wrapping this, like every live caller today) gets scroll-position preservation across the resulting reload for free — see macros/filter_tabs.html's doc comment (static/js/mp-scroll-restore.js, loaded globally, handles both the tab clicks and this form's submit). Nothing to add here; it's automatic as long as the search input sits inside a real , same as the Usage example below. - table_desktop() / table_mobile(): two distinct macros for the row list itself, same reasoning as kpi_card_desktop()/kpi_card_mobile() (macros/kpi_card.html) — table_mobile() is a real card list, not a table with columns hidden via CSS. Wrap the whole thing in class="card mp-data-table" (not just "card") — that scopes the Gray Scale rules in mp-components.css so the header labels, row-hover tint, and footer/pagination background all draw from the same two grays instead of three different (and, stacked together, visibly mismatched) Tabler defaults. See that CSS section's own comment for why. Both table macros take the same `rows` shape so a page renders both from one dataset (wrap each in its own d-none/d-md-block visibility, same technique the live pages already use for other elements): rows = [{ id: , avatar_name: , avatar_url: , primary: , secondary: (optional), mobile_secondary: (optional — falls back to `secondary`), cells: [], badges: [{text, variant}] (optional — shown under primary/secondary on BOTH table_desktop() and table_mobile(); variant is a Tabler color name used as bg--lt, e.g. "green"), mobile_badges: [{text, variant}] (optional — table_mobile() prefers this over `badges` when present, same reasoning as mobile_secondary/secondary above. Use this when the two views want different badge sets — e.g. desktop already has Status/ Active/Revenue as columns so `badges` there should stay to just what's NOT already a column, while table_mobile() has no columns at all and needs a fuller summary) (optional — falls back to `badges`), mobile_detail: (optional), actions: [] }, ...] When `rows` is empty, render table_empty_state() instead of table_desktop()/table_mobile() (see that macro's own doc comment below).
