Style Guide

The only components you should ever need. Never hand-roll a button, a dropdown, or a heading size — use these.

Page Layout

The container every real page-header/page-body actually renders with margins on. Get this wrong and a page looks fine on a quick desktop screenshot but is broken on mobile and misaligned on wide screens — this bit the Create Passport redesign (2026-09-07) before it was caught.

Use .dashboard-container for page-header and page-body content — never Bootstrap's own .container-xl. An app-wide !important override in static/minipass.css ("Fix Bootstrap container constraints in the new layout") strips all padding and max-width from .container-xl everywhere, so it renders completely edge-to-edge with zero gutter at every breakpoint. It's invisible on a wide desktop screenshot (the page just looks "full width") and very visible on mobile (text touches the screen edge). .dashboard-container (also in static/minipass.css) is the real, working primitive — max-width: 1400px, centered, with a responsive gutter (1.5rem desktop / 1rem mobile). Dashboard, Passports, and Activity Dashboard all use it; this style guide page didn't until this was found, which is exactly how the mistake propagated.

For a single-card form/detail page, don't center the card in a Bootstrap row.justify-content-center > col-lg-* — that centers a narrow column inside the container while the page-header's breadcrumb/title stay flush left, so the card ends up looking disconnected from the page above it (a big dead gap on one or both sides). Make the card a direct, full-width child of .dashboard-container instead, exactly like the redesigned passport_form.html — it then shares the same left edge and width as the header on every breakpoint, with no extra width decision to get wrong.

That full-width card fixes the header/card alignment, but on a wide monitor it introduces a different problem if the fields inside are left to stretch: an 1300px+ single-line text input (no basis in any form-usability guidance), and a submit button that ends up 1000px+ from the field the user just filled — a Fitts's-law/proximity violation that's easy to miss because it only shows up on a genuinely wide viewport (found on the Create Passport page, 2026-09-07). Fix: wrap the actual fields (and the footer's buttons, in the same wrapper) in .mp-form-content (max-width: 40rem, left-anchored, no auto margin) — the card surface stays full width and aligned with the header, but the content and the submit button both land in a sane, proximate column instead of sprawling edge to edge.

Submit-button placement: in the card footer, keep the button group inside the same .mp-form-content wrapper so it aligns with the fields above. Avoid pushing the buttons to the far right edge of the card — that breaks the form's visual boundary on wide viewports. Place the primary action first, then the secondary/cancel action next to it. Do not put Cancel first; the primary submit is the action the user is most likely to take and should lead the reading order. The left-to-right order is: primary action, then Cancel. (This exact mistake, Cancel-then-Submit, burned an hour on the Create Passport redesign on 2026-09-07.)

Typography

Fixed scale, Inter, one family. Headings are global (h1-h5) — never override size/color/font on a page.

H1 — Page title (24px / 600)

H2 — Section title (20px / 600)

H3 — Card / subsection title (18px / 600)

H4 — Minor heading (16px / 600)

H5 — Label / eyebrow (14px / 600, uppercase)

Body — description / secondary text (14px / 400). This is the .mp-text-body class.

Action Menu

Compact row/card actions dropdown. Replaces loose rows of View/Edit/Delete buttons. Default trigger is a plain three-dot (kebab) icon button — the standard "more options" pattern (Gmail/Drive/Notion/Linear/Airtable, and what this app used before the mp-* redesign), adopted here after trialing it live on Activities. No chevron alongside it: a chevron means "pick a value" or "expand," the kebab already means "menu of actions" on its own, and combining them mixes two different signifiers for one control. Also gets a coarse-pointer (real touchscreen) minimum 44×44px tap target automatically, both for this trigger and for the menu's own rows once open — see mp-components.css's @media (pointer: coarse) rules.
Rule: every action-menu item gets an icon before its label — no bare-text items. An icon-less row next to icon'd ones reads as unfinished, and the icon is what lets a user recognize an action at a glance instead of reading every row. Pass it as pre-rendered safe HTML on the item's icon key: "icon": '<i class="ti ti-pencil"></i>' (see the demo below — every item, including plain View/Edit ones, carries one). Pick a Tabler icon that actually matches the verb (ti-pencil for Edit, ti-eye for View, ti-trash for Delete, ti-currency-dollar for a payment action, etc.) rather than reusing one icon everywhere.
Rule: a destructive action (Delete, Remove, Cancel-permanently, etc.) is always styled red — a near-universal convention (macOS, Windows, GitHub, Gmail, Slack, Trello, Notion all do this), paired with a distinguishing icon and a confirmation step for anything non-trivial. In action_menu() items, set "attrs": {"data-variant": "destructive"} (see the Delete item in the demo below). In any remaining old-style <a class="dropdown-item"> markup, add Bootstrap's text-danger class the same way. Don't leave a delete action the same color as everything else in the menu.

Data Table

The shared shape behind the Orders/Products/Dashboard-history/Activities/Passports/Sign-ups/Interac Inbox/Surveys list pages: a toolbar (filter tabs centered, search icon collapsed to the left — expands inline on desktop, replaces the tabs entirely on mobile), table_desktop()/table_mobile() for the row list, and table_empty_state() for when there's nothing to show. Any new list/table page should adopt the recipe below rather than hand-rolling its own. Wrap the toolbar in a real <form method="get"> and scroll position across a filter/search reload is preserved automatically — see Filter Tabs above.
Plain lists with no identity/action column — e.g. Activity Log, a pure timestamp/type/message log — pass show_user=False, show_actions=False to both table_desktop()/table_mobile() to drop the fixed "User" and "Actions" columns entirely. Put an icon+label (or any other arbitrary content) straight into a cells entry on desktop; on mobile, since there's no avatar/primary/secondary block left, compose the whole card (icon+label, timestamp, message, small inline action icons) into mobile_detail's safe-html instead.
The full search + tabs recipe — this is what made Activities' search silently reset to its default tab until it was fixed; don't hand-roll this part again: build tabs with utils.py's tab_url(endpoint, current_filters, **overrides) instead of calling url_for() directly, so every tab link carries the current search/filters forward automatically. Then wrap the toolbar's <form> with {{ '{{ preserve_filters(current_filters) }}' }} so submitting a search carries the current tab forward too. If a scoped search comes up empty but matches exist on another tab, pass other_matches_count/compute a tab_url(..., status=None, show_all='true') link into table_empty_state() instead of leaving a dead end.
